## 1. 现状盘点（截图 2 的四列是怎么来的）

当前主窗口一行内并存的四个纵向区域：

| 列 | 归属 | 能否移动/隐藏 |
| --- | --- | --- |
| ① 文件/git 侧栏 | 我们的 WebContentsView | ✅ 可显隐/调宽（已有） |
| ② dsh 自带会话列表 | **dsh 页面自身 UI** | ❌ 不可动（侵入红线） |
| ③ dsh 对话主区 | dsh 页面自身 UI | ❌ 不可动 |
| ④ 监控面板（变更审查） | 我们的 WebContentsView | ✅ 可显隐/调宽（已有） |

再加底部日志条 + 状态条，纵向也被切两刀。**难用的根源不是功能缺失，
而是 ①②④ 同时展开时 ③（用户真正工作的区域）被压到中间一条。**

Reasonix 之所以好看：它只有「1 导航 + 对话 + 1 情报面板」，且每个区域
信息密度高、视觉安静。

已核实的技术事实（rc.2 运行副本源码验证）：

1. `session.list` 返回字段：`sessionId / updatedAt / running /
   parentSessionId / origin / cwd / agentPreset` —— **没有标题/描述字段**。
2. mux 事件流里有 `user/message` 事件（含用户文本）—— 会话标题可以从
   首条用户消息截断推导。
3. token-meter 投影里已定义 `contextPressure` / `contextBreakdown`
   投影键 —— Reasonix 右侧那个「上下文 5.7K/1M」进度条的数据源存在，
   我们的 event-store 目前只收 `sessionStats`/`tokenUsage` 两个键。
4. dsh 前端（ui-conversation）**没有任何 URL 路由**（无 hash /
   searchParams / pushState）—— 会话切换只能在其自带 UI 里做，
   外部无法用导航方式直达某个会话。

### 2.1 专项：命中率与费用（用户重点）

**命中率：✅ 完全支持，纯推导，零新增数据。**
`tokenUsage` 投影（已在收）有四桶：`cacheRead / cacheWrite /
uncachedInput / output`。命中率 = `cacheRead ÷ (cacheRead + uncachedInput)`
（Reasonix 同口径；缓存写入是否计入分母做成口径选项即可）。底条直接加一段。

**费用：✅ 可实现，但性质是「本地估算」，不是上游数据。** 已核实的边界：

1. **dsh 会话数据不记钱。** 全 harness 检索：usage 投影只有 token 四桶，
   事件与投影里没有任何金额字段。唯一的价格概念在外部库
   `@earendil-works/pi-ai` 的内置模型目录（`ModelCost = {input, output,
   cacheRead, cacheWrite}` 单价），且 harness 自定义的模型条目默认
   `NO_COST`（全零）——**依赖它不可移植**。
2. **因此费用只能自己算**：`费用 = Σ(token桶 × 单价)`，单价来自一张
   **用户可编辑的价格表**（按模型名匹配，元/百万 tokens）。机制本身
   **不锁 DeepSeek**——任何模型配了价就能算；没配的显示 `–`。预置
   DeepSeek 官方价（如 V3.2：命中输入 ¥0.2/M、未命中 ¥2/M、输出 ¥3/M，
   来源 api-docs.deepseek.com，价格可变需可改）。
3. **关于 Reasonix 的「要 API key」**：查证（github.com/esengine/
   DeepSeek-Reasonix，MIT）——它是 DeepSeek-native 设计（官方 FAQ 明说
   「只支持 DeepSeek 是设计选择」），key 是它**运行的前提**，不是费用
   功能单独要的；费用 = 发布价 × token 用量的本地乘法。**我们的 dsh
   同样跑在用户自己的 key 上，但费用估算本身不需要 key。**
4. **可选增强（真要 key 的场景）**：显示「账户余额」才需要 key——
   DeepSeek 平台有 `/user/balance` 接口。做成可选项：用户在设置里填了
   key 才启用，且仅对 DeepSeek 官方端点有意义。默认不做。
5. **精度边界要诚实**：价格表按模型名匹配，而会话实际模型可能中途
   切换、名字可能与官方价目对不上（如截图中 `DeepSeek-V4-Flash 97315`
   这类部署名）——所以费用标注「估算」，模型未配价时显示 `–`，
   允许用户在价格表里加别名。

**结论：底条完整费用段（四桶 token + 命中率 + 估算费用）全部可行；
命中率零成本，费用需要一张用户可编辑的价格表 + 「估算」标注。**
MCP 面板按用户决定砍掉。

## 3. 演进方案（不推翻，三层递进）

### 第一期：右侧面板「概览」Tab + 布局预设（低风险，直接治难用）

- event-store 增收 `contextPressure` / `contextBreakdown`（沿用现有
  higher-seq-wins 投影机制，KEPT 集合加两个键）。
- 监控面板改双 Tab：**变更审查**（现状）| **会话概览**（上下文进度条、
  token 构成、运行指标 —— Reasonix 右栏的等价物）。
- 布局预设三档接入命令面板/菜单：**专注**（侧栏收、面板开）、**经典**
  （现状默认）、**极简**（全部收起）。偏好持久化，已有机制直接用。

### 第二期：左侧「会话」导航视图（Reasonix 左栏的等价物）

- 侧栏双 Tab：**文件** | **会话**。会话视图按 cwd 分组（= Reasonix 的
  「项目」），会话行 = 标题（首条消息截断）+ 相对时间 + 运行状态点 +
  agentPreset 徽标。
- 联动：点击会话 → 文件树定位其 cwd；双击 → logbar 过滤该会话的
  Agent 活动（event-store 已有 sessionId 维度）。

### 第三期：底条费用段 + 价格表

- 状态栏追加费用段：四桶 token、命中率（cacheRead 占比）、估算费用
  （¥，价格表 × tokenUsage）。
- 价格表 = 用户可编辑配置（按模型名/别名匹配，元/Mtok），预置
  DeepSeek 官方价；未配价模型显示 `–`。
- 可选：设置里填 DeepSeek key 才启用的「账户余额」显示
  （`/user/balance`），默认不做。
- MCP 面板：用户决定不做。

### 明确不做

- 会话切换、动 dsh 自带列、改 dsh 视觉 —— 红线内全部放弃；
  对应能力仍在 dsh 自己的 UI 里完成（这本来就是 dsh 的职责）。
