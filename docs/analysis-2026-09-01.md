### 3.1 需求

窗口内可调整大小的右侧分屏，显示 git 状态与文件列表，点击文件可查看更改。

### 3.2 方案：双 WebContentsView

主窗口 `contentView` 下并列两个 `WebContentsView`：

- **侧栏视图**：`assets/sidebar.html`，独立 preload，`contextIsolation: true`

Electron 33.4.11 已确认支持 `BaseWindow.contentView.addChildView()` 与
`WebContentsView.setBounds()`。

### 3.3 上游侵入性判定

| 项 | 结论 |
| --- | --- |

### 3.5 认证：一个必须澄清的误解

rc.2 **没有 token**。上游只打印 `dsh web: <url>`（无 token），且 `packages/client/connection/src/`
下无 `randomBytes`。认证实际只有 **loopback Host 头围栏**，上游 README 明示「这不是认证层」。

shell `launcher.ts` 里那套 token 捕获是防御性代码——留着无害，但**不能当契约依赖**。
侧栏调 `/api/*` 必须两种版本通吃：带上主窗口 URL 里捕获到的 token（有则带，无则裸调）。

### 3.6 「跟随当前会话目录」的实现路径

`SessionSummary` 自带 `running` 与 `updatedAt`，因此**无需注入页面**：

1. 调 `session.list` 取全部会话的 `cwd`，去重成目录列表
2. 优先取 `running: true`，否则按 `updatedAt` 降序 → 推「最近活跃会话」
3. 侧栏顶部提供下拉，可随时手动切换或选择任意文件夹

语义从「当前会话」降为「最近活跃会话」—— 实践中绝大多数场景两者一致，
代价远小于注入页面（方案 C，上游改版即碎）。

### 3.7 git 数据源

优先 spawn 系统 git（`git status --porcelain -z -uall`、`git diff -- <path>`），
检测不到时回落已依赖的 `isomorphic-git`（harness 仓库 9000+ 文件，`statusMatrix` 明显慢，
不能当主路径）。

### 3.8 写操作护栏（若后续扩展到 commit/checkout）

**真实冲突**：shell 自动更新会对 `workspace.dir` 执行 `git fetch` / `git reset --hard`。
侧栏若对同一目录做写操作，会争抢 `.git` 写锁，最坏情况把刚提交的内容 reset 掉。

三条护栏：

1. 监控目录 == `launcher.sourceDir` 时**禁用全部写操作**，UI 明示「此目录由自动更新管理」
2. 写操作前检查 `.git/index.lock`，存在则拒绝并提示
3. `checkout` 等破坏性操作二次确认

## 4. 功能全景与优先级

侧边栏不是孤立功能——它标志着 shell 从「**启动器**」向「**IDE 式工作台**」转型的第一步。
一旦有了侧栏容器，底部面板、命令面板、多标签都会自然跟进。因此建议**先定容器架构，再填功能**。

| 优先级 | 功能 | 价值 | 成本 | 说明 |
| --- | --- | --- | --- | --- |
| P0 | 侧栏容器（双视图 + 拖拽 + 显隐持久化） | 高 | 中 | 后续所有面板的承载体，先做骨架 |
| P0 | git 只读面板（分支 / 变更 / 文件树 / diff） | 高 | 中 | 本期核心诉求 |
| P1 | 底部面板（日志 / 输出） | 高 | 低 | 4 份日志现散在 `%APPDATA%`，用户看不到 |
| P1 | 设置界面 | 高 | 中 | 当前设置散在 wizard + 菜单，无常规入口 |
| P1 | 诊断自检面板 | 中 | 低 | 打包/环境问题自查，降低支持成本 |
| P2 | 命令面板 (Cmd/Ctrl+K) | 中 | 中 | 依赖容器架构就绪 |
| P2 | 多会话 / 多标签 | 中 | 高 | 依赖 `session.list` 稳定性 |
| P2 | git 写操作（暂存 / 提交 / 切换分支） | 中 | 高 | 必须配 3.8 的护栏 |
| P3 | 工作区切换器 | 中 | 中 | 与会话跟随功能重合，可合并 |
